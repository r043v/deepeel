## Objectif : main générique + campagne multi-ROMs + analyse globale du résidu

Constat (relevé par 3 agents) : le `explore` actuel est mono-ROM à murs constants (queue 4096, closure 4 rounds, TAS jamais découvert automatiquement), aucun artefact de profilage compact (le JSON omet `forks_capped`, `halt_cuts`, `exec_outside`, toute la famille `closure_*`), aucune agrégation multi-ROM. Best-of actuel : SML1 99,9 %, SML2 62,9 %, Zelda 58,7 %, Mystic Quest ~14 % — chacun avec une recette différente cousue main. Le parc : 5 ROMs (SML1, SML2, Zelda LA, Mystic Quest, Pokémon Jaune GBC/MBC5 jamais testée) et 12 films TAS locaux déjà téléchargés.

### 1. Moteur — le main générique devient auto-profilié (v0.9.0)
- **File de travail adaptative bornée** : nouveau `DpConfig.queue_max` (défaut 4× queue_cap, flag `--queue-max`). Quand la file principale est pleine : croissance ×2 (ring recopié ordonné) tant que `q_cap < queue_max` **et** RSS < mem-cap si actif ; compteur `queue_growths` rapporté ; croissance refusée → perte comptée `queue_overflows` comme aujourd'hui. `dp_rss_mb()` sort de sessions.c (static) vers explorer.c/explorer.h. `--mem-cap` remplit aussi le nouveau `cfg.mem_cap_mb`. Fini les 60 835 chemins entiers jetés sans que la RAM n'explose — borné par `queue_max` + mem-cap, jamais silencieux.
- **Mur horloge gracieux** : `--time-limit SEC` (défaut 0 = off) dans la boucle de jeu — arrêt gracieux (raison « time budget », pool sauvegardé). Les phases d'analyse d'après restent bornées en pas. Un scan devient auto-borné sans babysitting par signaux.
- **Découverte TAS** : `--tas-dir D` — collecte ≤8 films (.vmv/.bk2/.gbm/.log) du répertoire, triés par similarité de titre avec la ROM si trop nombreux, retenus loggés sur stderr.
- **closure_rounds** défaut 4 → 12 (la boucle sort déjà dès qu'un round ne sème plus rien : coût nul sur les ROMs silencieuses).
- **Artefact de profilage `--summary f`** : JSON compact — identité ROM, écho config, résumé carte (toutes classes + %), liste **complète** des plages résiduelles via `dp_map_residual_list()` (refactor de `dp_map_residual_text` dessus), **tous** les compteurs `DpResults` (y compris les silencieux), stats tree, faits de jeu (frames, tas_n, raison d'arrêt). C'est l'entrée de l'agrégation.
- **`--json`** : ajoute les compteurs manquants + une section « map » (résumé + résiduel).
- **Rapport texte** : ligne budgets gagne `forks_capped` et les croissances de file ; `exec_outside` visible. `usage()` à jour. Version **0.9.0**.
- **Tests** : bloc test_explorer « la file pousse jusqu'à queue_max puis compte les pertes » (queue_cap minuscule, fixture qui fourche ; vérifie `queue_growths > 0`, pertes nulles sous le cap, chemins exécutés > cap initial). ctest 6/6 vert.

### 2. Outil batch — `tools/scan_all.py` (précédent : tools/tasvideos_fetch.py)
- **scan** : énumère `--roms` (défaut ~/dev/m0boy/roms/gb, ignore README/profiles), slug par titre, politique unique par taille : `--play --queue 4096 --queue-max 16384 --mem-cap 2000 --covered-keep 8 --seed-banks --closure-rounds 12 --time-limit 1800` + max-total étagé (≤16 banques 100M, ≤32 200M, au-delà 300M) ; mines les films TAS localement (output/tas, récursif, similarité de titre, ≤8 `--tas`, `--tas-solo` si TAS) sinon sessions aléatoires. Séquentiel, sorties `output/batch/<slug>/` (summary.json, .txt, .map.png, .log, state-dir), l'échec d'une ROM n'arrête pas la campagne, `--only <slug>`.
- **digest** : agrège les summary.json → `output/batch/REPORT.md` : tableau par ROM (connu %, inconnu, inféré, compteurs de saturation), union des plages résiduelles, classement des mécanismes bloquants. Les .map.png portent la carte complète embarquée (chunk `deepeel_map`) pour l'analyse octet-par-octet.

### 3. Campagne de mesure (bornée, puis Zelda à fond)
Ordre : **SML1** (régression, 7 films, attendu ≥99,9 %) → **SML2** (2 films) → **Mystic Quest** (sans TAS, MBC2 : le vrai test du main générique) → **Pokémon Jaune** (sonde GBC/MBC5, 1 MiB) → **Zelda** (3 films, 30 min). Puis **Zelda à fond en arrière-plan** (`--only zelda`, sans time-limit, avec `--resume` pour repartir du pool) pendant que j'analyse le reste. RAM plafonnée (`--mem-cap 2000`), tout séquentiel. Les nombres restent des observations de l'outil, jamais des mesures de matériel.

### 4. Analyse globale — ce qui manque pour débloquer le 100 % (livrable principal)
Par ROM, classification octet-par-octet du résidu par **mécanisme bloquant** : queues de conditions jamais branchées, data jamais lue au-delà des caps d'inférence, cibles de dispatch non prouvées, ambiguïté de banque restante, pertes par saturation (`queue_overflows`, `forks_capped`, refus), murs touchés (`budget_steps`, time budget). Tableau croisé du parc : ce qui bloque à l'échelle globale (pas de TAS pour Mystic, MBC2, GBC, fourches de queues de conditions…). Recettes futures **classées par octets débloqués** — la feuille de route honnête vers 100 %. Rapport généré + synthèse finale ici ; README et docs/GB.fr.md mis à jour.
